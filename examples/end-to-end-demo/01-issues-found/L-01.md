# [LANE L] Issue L-01: Missing CI/CD workflow configuration

- Type Tags: L-Issue, CI-CD, Missing-Infrastructure
- Severity: 5/10 (MEDIUM)
- Status: OPEN
- Date Discovered: 2026-04-23

## Problem Description

- **What is wrong:** Repository has **no `.github/workflows/` directory**, so there is no automated CI on PR / push. The framework ships 247 Python tools, and none of them are exercised by CI.
- **Expected:** At least one workflow that runs on every push / PR to `main` — e.g. lint, syntax check, or a smoke test that imports each tool module.
- **Actual:** `.github/` does not exist at all at the repo root.
- **Scope:** Entire repo. A stranger cloning the project sees "production-grade multi-agent framework" in the README, but there is no continuous verification of that claim.

## Evidence

```bash
$ ls -la .github/ 2>&1
ls: .github/: No such file or directory

$ ls tools/ | wc -l
247

$ grep -rn "github/workflows" README.md ARCHITECTURE.md docs/ 2>/dev/null
# (no matches — nothing documents CI either)
```

- **Source:** repository root — `.github/` directory is absent

## Fix Requirements (DO NOT IMPLEMENT)

- [ ] Create `.github/workflows/` directory
- [ ] Add a minimal CI workflow (e.g. `ci.yml`) that at least runs `python3 -m py_compile tools/*.py` on `push` and `pull_request`
- [ ] Optionally add a job that exercises the key issue-management tools (`add_issue.py`, `sync_catalog_stats.py`, `verify_issue.py`)
